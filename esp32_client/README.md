# Клиент Ирины для комнаты (ESP32)

Небольшое устройство в каждой комнате: микрофон слушает, когда в комнате говорят — звук уходит на сервер
(приставка с `runva_rooms.py`), сервер распознаёт речь, выполняет команду и присылает голосовой ответ
обратно в эту же комнату.

```
 ESP32 (кухня)  ──Wi-Fi──┐                      ┌── Home Assistant
 ESP32 (спальня) ─Wi-Fi──┼──►  приставка RK3528  ├── Яндекс Музыка (играет на приставке)
 ESP32 (детская) ─Wi-Fi──┘    распознавание Vosk └── ответ голосом → в ту комнату, где спросили
                              синтез vosk-tts
```

## Железо

| Компонент | Пример | Примечание |
|---|---|---|
| Плата | ESP32 DevKit (WROOM-32) или ESP32-S3 DevKitC | ESP32-C3/C6 не подойдут: у них один I2S |
| Микрофон | INMP441 (I2S) | SPH0645 тоже работает, может понадобиться больше усиления |
| Усилитель | MAX98357A (I2S, 3 Вт) | + динамик 4–8 Ом |
| Питание | USB 5 В, 1 А | усилитель питайте от 5 В |

### Подключение: ESP32-S3 N16R8 (модуль в адаптере для WROOM-32E)

Модуль вставляется как WROOM-32E: антенной от колодки. Подписи на гребёнке адаптера — от WROOM-32,
поэтому подключаем по ним:

| Подпись на адаптере | GPIO S3 | Куда |
|---|---|---|
| SVP | 4 | INMP441 SCK |
| SVN | 5 | INMP441 WS |
| IO34 | 6 | INMP441 SD |
| IO35 | 7 | MAX98357A DIN |
| IO32 | 15 | MAX98357A BCLK |
| IO33 | 16 | MAX98357A LRC |
| 3V3 | — | INMP441 VDD |
| GND | — | GND микрофона и усилителя, INMP441 **L/R** — обязательно, коротким проводом прямо у микрофона |
| 5V | — | MAX98357A VIN |

Если L/R «висит» или плохо держит контакт, микрофон перескакивает между слотами I2S: звук рвётся и звучит
неестественно, а в мониторе у «пустого» слота заметно больше 0% живых отсчётов.

MAX98357A: SD и GAIN не подключать (усилитель включён, 9 дБ). GPIO 35–37 заняты PSRAM — к ним ничего,
светодиод адаптера «LED-IO4» сидит как раз на GPIO35 (если будет ошибка PSRAM — отпаять его).
На ESP32-S3-DevKitC-1 — те же номера GPIO.

### Подключение: ESP32 DevKit (WROOM-32)

| INMP441 | ESP32 | | MAX98357A | ESP32 |
|---|---|---|---|---|
| VDD | 3V3 | | VIN | 5V |
| GND | GND | | GND | GND |
| L/R | GND | | BCLK | GPIO 26 |
| SCK | GPIO 32 | | LRC | GPIO 27 |
| WS | GPIO 25 | | DIN | GPIO 22 |
| SD | GPIO 33 | | GAIN | не подключать (9 дБ) |

Пины меняются в `IreneClient/config.h`. Микрофон ставьте подальше от динамика и не направляйте на него.

## Прошивка в Arduino IDE

1. **Ядро ESP32.** Инструменты → Плата → Менеджер плат → **esp32** (Espressif Systems), версия 3.x (проверено на 3.3.12)
   или 2.0.17.
2. **Библиотеки.** Скетч → Подключить библиотеку → Управлять библиотеками: **WiFiManager** (tzapu),
   **WebSockets** (Markus Sattler), **ArduinoJson** (Benoit Blanchon), версия 7.
3. **Откройте** `esp32_client/IreneClient/IreneClient.ino` (вкладка `config.h` — распиновка).
4. **Инструменты:**

   | Пункт | ESP32-S3 N16R8 (через адаптер) | ESP32 DevKit |
   |---|---|---|
   | Плата | ESP32S3 Dev Module | ESP32 Dev Module |
   | USB CDC On Boot | **Disabled** | — |
   | CPU Frequency | 240MHz (WiFi) | 240MHz (WiFi) |
   | Flash Mode | QIO 80MHz | QIO |
   | Flash Size | **16MB (128Mb)** | 4MB |
   | Partition Scheme | **16M Flash (3MB APP/9.9MB FATFS)** | Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS) |
   | PSRAM | **OPI PSRAM** | — |
   | Upload Mode | UART0 / Hardware CDC | — |
   | Upload Speed | 921600 (при ошибках — 460800) | 921600 |
   | Erase All Flash Before Sketch Upload | Enabled — только первый раз | Enabled — только первый раз |
   | Порт | COM-порт адаптера (CH9102) | COM-порт платы |

   PSRAM обязательно «OPI»: с другим значением модуль N16R8 не запустится или не увидит память.
   USB CDC On Boot — Disabled: прошивка и монитор порта идут через микросхему адаптера, а не USB самого S3.
   Для платы DevKitC-1 через разъём «USB» (не «UART») — Enabled.
5. **Загрузить**, затем Монитор порта на **115200**. Если адаптер не перевёл модуль в режим прошивки — зажать PROG,
   нажать RST, отпустить PROG.

В мониторе должно быть: `Клиент Ирины 2.0`, `Чип ESP32-S3, PSRAM 8192 КБ`. Если PSRAM 0 — проверьте пункт PSRAM.

Обновление по Wi-Fi: после первой прошивки клиент появится в «Инструменты → Порт» как сетевой порт
`irene-<комната>`; пароль — ключ из настроек.

## Настройка

1. После прошивки клиент создаёт точку доступа **Irene-XXXXXX**. Подключитесь к ней с телефона — откроется портал.
2. Выберите домашнюю сеть Wi-Fi, введите пароль и заполните поля:
   - **Адрес сервера** — IP приставки или `irene.local` (если имя приставки `irene`);
   - **Порт** — `8765`;
   - **ID комнаты** латиницей — `kitchen`, `bedroom`…
   - **Название комнаты** — точно как зона в Home Assistant: `Кухня`, `Спальня`. Тогда «Ирина, включи свет»
     включит свет именно в этой комнате;
   - **Ключ** — значение `token` из `runva_rooms.json` на приставке.
3. Сохраните. Клиент перезагрузится и подключится к серверу (в логе сервера появится «Подключилась комната …»).

Изменить настройки потом: откройте в браузере `http://<IP клиента>/` → **Setup** (IP клиента пишется
в мониторе порта и виден в списке устройств роутера). Ключ на странице не показывается — оставьте поле
пустым, чтобы его не менять. После сохранения клиент перезагрузится.

Сбросить все настройки, включая Wi-Fi: удерживать кнопку BOOT 5 секунд (светодиод помигает).

Если страница 192.168.4.1 не открывается при первой настройке — телефон, не найдя интернета в сети
Irene-XXXXXX, мог уйти на мобильные данные: отключите их на время настройки.

Обновление по Wi-Fi: `pio run -e esp32dev_ota -t upload --upload-port irene-kitchen.local`
(пароль — тот же ключ, раскомментируйте `upload_flags` в `platformio.ini`).

## Как это работает

- Клиент постоянно читает микрофон и сравнивает уровень звука с фоновым шумом. Когда кто-то говорит,
  он отправляет звук на сервер (вместе с 0,4 с до начала речи), а после 0,8 с тишины — сообщает о конце фразы.
  Так сервер не тратит процессор на тишину во всех комнатах.
- Сервер распознаёт фразу. Если в ней есть «Ирина» — выполняет команду и присылает ответ голосом.
  Как только сервер слышит «Ирина», загорается светодиод, и клиент ждёт продолжения команды дольше (1,6 с).
- Можно сказать «Ирина», дождаться светодиода и сказать команду отдельно.
- Если одну фразу услышали клиенты в соседних комнатах, команда выполнится один раз, а ответ прозвучит там,
  где голос был громче.
- Пока клиент говорит, он не слушает микрофон — Ирина не реагирует на собственные ответы.

## Настройка чувствительности

С прошивки 2.0 — в веб-интерфейсе сервера, вкладка **Комнаты**, применяется сразу:

- **Автоусиление** (включено по умолчанию): после каждой фразы усиление сдвигается к уровню речи ~2500 — вверх до 3 дБ
  за фразу, вниз осторожнее; посреди фразы не меняется; уровень считается только по звучащим кадрам; щелчки и хлопки
  не учитываются; фоновый шум не поднимается выше 400; при речи с искажениями (выше 15000) — сразу вниз.
  Диапазон 6 дБ … «Не больше» (по умолчанию 30 дБ). Подобранное значение сохраняется раз в 5 минут.
- **Микрофон** — ручное усиление, если автоусиление выключено.
- **Порог** — с какого уровня звук считается речью (по умолчанию 250). Реагирует на шум → больше; не слышит тихую речь → меньше.
- **Пауза** — сколько тишины ждать до конца фразы (1000 мс). Обрезает конец фразы → 1200–1500.
- **Индикатор** — живой уровень микрофона (только пока открыта страница): зелёные риски — хорошая речь (1500–5000),
  оранжевая — порог начала речи.

То же есть на странице клиента `http://<IP клиента>/` → **Setup** (после сохранения клиент перезагрузится).
В мониторе порта после каждой фразы:
```
Фраза 2.1 с: уровень речи 2400, шум 80, порог 250, усиление 18.0 дБ (авто)
Автоусиление: 18.0 -> 19.5 дБ (уровень фразы 2400, цель 3000)
```

Одиночные сбои шины I2S (щелчки на всю шкалу) прошивка 2.3 убирает сама — в мониторе «убрано щелчков N».
Если их много (десятки за фразу) — укоротите провода микрофона (до 10–15 см), поставьте керамический конденсатор
0,1 мкФ прямо на VDD/GND микрофона и проложите GND микрофона отдельным проводом.

Клиент сам выбирает слот I2S, в котором говорит микрофон (с 2.2; в мониторе порта — «Микрофон: слот …»).
Если там «оба слота молчат» — проверьте провода SCK/WS/SD и питание микрофона. Задать слот вручную — `MIC_SLOT` в `config.h`.

## Если клиент теряет Wi-Fi

Клиент пишет в монитор порта и сообщает серверу (видно в логе при подключении):
причину последнего запуска, уровень сигнала и число обрывов.

| Признак | Что делать |
|---|---|
| `Причина запуска: ПРОСАДКА ПИТАНИЯ (brownout)` или обрывы, когда Ирина говорит | Питание: блок 5 В от 1–2 А, короткие толстые провода, конденсатор 470–1000 мкФ на VIN/GND усилителя и 100 мкФ у ESP32. Помогает и `WIFI_TX_POWER WIFI_POWER_15dBm` в `config.h` |
| Перезагрузка на большой громкости | Просадка питания от пиков тока усилителя (на 100% — больше 1 А). Блок 5 В 2 А и короткий толстый кабель; конденсатор 470–1000 мкФ прямо на VIN/GND усилителя и 100 мкФ на 3V3/GND модуля; усилитель питать отдельным проводом от блока, а не через адаптер; в `config.h` — `VOLUME_LIMIT_PCT` (по умолчанию 80) |
| Сигнал −75 дБм и хуже, код обрыва 200/201/4 | Слабый сигнал: ближе к роутеру, плата с внешней антенной (ESP32-WROOM-32U), репитер |
| Обрывы при хорошем сигнале и питании | Роутер: для 2,4 ГГц выключите «умное» переключение диапазонов (band steering), поставьте ширину канала 20 МГц, фиксированный канал 1/6/11, режим WPA2 (не WPA3). Закрепите за клиентом IP в DHCP |

Клиент сам переподключается каждые 5 секунд, а если сеть не вернулась за 2 минуты — перезагружается.

## Если клиент не стартует или ведёт себя странно

В монитор порта после `entry 0x400...` ничего не выводится, клиент сам перезагружается или зависает —
сотрите память целиком и прошейте заново. Часто мешают остатки старой прошивки или другой разметки памяти.

- Arduino IDE: «Инструменты → Erase All Flash Before Sketch Upload → Enabled» → Загрузить → верните Disabled;
- или в браузере (Chrome/Edge): https://espressif.github.io/esptool-js/ → Connect → Erase Flash.

После стирания настройки (Wi-Fi, сервер, ключ) пропадут — настройте клиент заново через точку доступа Irene-XXXXXX.
